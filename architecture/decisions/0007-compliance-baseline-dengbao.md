# ADR-0007：合规基线锚定等保2.0三级、全局基线按租户可收紧不放松

> ADR = Architecture Decision Record（架构决策记录），记录本决策"为什么"。见 [ADR-0001](0001-record-architecture-decisions.md)。
> 名词：等保 2.0 = 中国网络安全等级保护（GB/T 22239，按系统重要性分级）；
> ISO 27001 = 国际信息安全管理体系认证；SOC 2 = 面向欧美客户的安全审计报告。

- **状态**：accepted
- **日期**：2026-06-20
- **关联**：与 [ADR-0005](0005-rbac-self-built-per-tenant.md)（权限）、[ADR-0006](0006-audit-unified-stream.md)（审计）协同；
  对应 2026-06 平台底座（在途 changes/）决策 D4。

## 背景
平台面向 ToB，需定合规基线：对齐哪个标准 / 等级，以及安全策略（口令 / 会话 / 锁定 / 加密等）作用域。

## 决策
1. **基线锚点 = 等保 2.0 三级**：以国内 ToB 常见的三级要求为**合规下限**；基线项**预留映射到 ISO 27001 / SOC 2 控制项**，
   出海 / 国际客户时叠加，不重做系统。
2. **策略作用域 = 全局默认基线（floor）+ 按租户可收紧不可放松**：平台定下限，租户只能更严、不得低于基线。
   db-per-tenant 下每租户策略天然独立，便于按租户收紧。
3. **可配置安全策略（平台一次满足、业务复用）**：身份鉴别（唯一标识、口令复杂度/有效期、登录失败锁定、
   三级要求的双因素之一）、会话（非活动超时、并发控制）、权限（最小权限 / 职责分离，由 RBAC 落地）、
   审计（覆盖每用户 / 关键事件 / 记录保护，由审计模块落地）、加密（传输 TLS、口令加盐哈希 bcrypt/argon2、
   敏感数据加密 + 密钥管理）。

## 取舍 / 备选方案
- **锚等保二级**：要求更低、成本低，但金融 / 政务等高要求客户可能不够；未选。
- **不锚定具体等级、只做共性基线**：灵活，但投标 / 客户尽调时可能需临时补齐到某级；未选为锚点（共性基线仍全做）。
- **策略全局统一、不可调**：管控最简，但无法满足个别客户"我要更严"；未选。
- **按租户完全自定义（含可放松）**：最灵活，但租户可能把安全调弱、击穿平台合规底线；未选。
- 故取"**锚三级 + floor 模型**"：既守住合规下限，又给客户向上收紧的弹性。

## 影响
- 需要一个**安全策略模块**：参数化口令 / 会话 / 锁定等，全局默认 + 按租户覆盖（仅允许收紧）。
- 与 D2（权限）、D3（审计）的实现共同构成合规能力；口令哈希、TLS、密钥管理为底座必备项。
- 等保三级的"双因素"等要求影响认证（authn）设计，需在 specs 中细化到具体控制项与测试。
