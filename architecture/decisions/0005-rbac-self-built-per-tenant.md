# ADR-0005：授权采用自研 RBAC（资源+动作）、各租户库自存、平台运营中心独立

> ADR = Architecture Decision Record（架构决策记录），记录本决策"为什么"。见 [ADR-0001](0001-record-architecture-decisions.md)。
> 名词：RBAC = 基于角色的访问控制（用户→角色→权限，权限=资源+动作）；
> data scope = 数据级权限（细到"仅本部门/本人"）；ABAC = 基于属性的访问控制。

- **状态**：accepted
- **日期**：2026-06-20
- **关联**：承接 [ADR-0004](0004-multi-tenant-db-per-tenant.md)（db-per-tenant）；
  对应 2026-06 平台底座（在途 changes/）决策 D2。

## 背景
平台底座需定授权（authz）模型：粒度、技术实现、以及在 db-per-tenant（每租户独立库、数据可驻留客户侧）
下用户与权限数据的落点。

## 决策
1. **自研 RBAC（不引入 Casbin）**：`用户—角色—权限`，权限 = **资源 + 动作**（可选角色继承）；
   接口层中间件按 `路由→(资源,动作)` 强制校验，越权拒绝；判定结果用 Redis 短缓存。
2. **粒度一期 = 资源+动作**；预留数据级权限 / ABAC 扩展位，一期不实现。
3. **数据落点 = 各租户库自存**：每租户的用户/角色/权限存该租户自己的库（与数据主权一致）；
   登录走"先定位租户 → 连其库认证"。
4. **平台运营中心（控制平面，新增能力）**：面向平台运营人员，职责包括创建租户、重置租户管理员密码、
   分配用户额度/坐席、资源额度管理、租户对象生命周期管理；其自身权限走平台级 RBAC，数据在控制平面中心库。
   与"租户自助管理"分属两个面。
   > **补注（2026-06-20 复审）**：其中**额度 / 坐席 / 资源额度 属块2 的「商业化子域」**（本轮不展开其详细设计；SSOT=平台中心库）。
   > 块2 一期主线职责 = 租户 CRUD / 生命周期 / 开通自动化 / 重置租户管理员密码 / 平台级 RBAC / 系统设置。

## 取舍 / 备选方案
- **Casbin**（Go 主流权限引擎，原生多租户域、可平滑升级 ABAC）：在本项目 db-per-tenant + 各租户库自存策略 +
  客户可能自托管远程库 下，需"每租户 enforcer + 指向其库的 adapter + 跨实例 watcher 同步"，跨网 reload 复杂度高，未选。
- **自研**：一期仅资源+动作时很轻，与业务数据同库同事务、同备份同迁移单元，对远程库更稳，故选。
- **代价**：角色继承/缓存/失效自行维护；将来上 ABAC 需自己扩（见下评估）。

## 扩展性评估（现在预留 vs 将来上数据级权限）
- **现在预留（成本低）**：权限/角色表加可空 `data_scope` 字段；中间件留"数据范围过滤"挂载点（一期 no-op）；
  业务查询**统一走仓储层范围注入口**；业务实体**携带归属属性（owner/部门）**。
- **将来上数据级权限（有预留→局部新增）**：实现"角色→数据范围"解析器 + 填挂载点 + 管理 UI；业务查询几乎不动。
- **若不预留（高）**：逐条改写所有业务查询 + **逐租户库回填归属字段与数据迁移**（db-per-tenant 逐库跑）。
- **结论**：预留把后期从"横切重构"降为"局部新增"。**最关键的两项现在就要留**：仓储层统一范围注入口、业务实体归属属性
  （跨 per-tenant 多库回填代价最大）。

## 影响
- 形成**平台级 RBAC**（运营/超管，控制平面）与**租户级 RBAC**（租户库内）两套作用域。
- **平台运营中心**为本变更新增能力，略微扩展 proposal 的"租户管理"；其中**用户额度 / 坐席 / 资源额度 属块2 的「商业化子域」**（本轮不展开详细设计；SSOT=平台中心库）。
- 业务实体需从一开始携带归属属性、并通过仓储层统一范围注入口访问数据（为数据级权限留种）。
