## 阶段 1 · 契约与骨架（T0 后）

- [ ] **T1 · server 行走骨架（walking skeleton）** ⛔阻塞(待 T0)
  - 输出：gale 起最小 HTTP 服务 + 健康检查；分层目录（handler→service→repo，领域内核不依赖框架）；
    产物输出 `bin/`（见全局 7、8）。写最小启动冒烟测试。
  - 验收：`go build` 入 `bin/`、服务起得来、健康检查 200、冒烟测试过。
- [ ] **T2 · OpenAPI 契约首版** ⛔阻塞(待 T0)
  - 输出：在 [../../contracts/openapi](../../contracts/README.md) 定义租户/认证/用户/角色权限/审计 API 契约。
  - 验收：契约校验通过；前端可由 openapi-typescript 生成类型化客户端。
- [ ] **T3 · 架构门禁自动化（fitness function）**（已登记待办，移至此处执行） ⛔阻塞(待 T1)
  - 在 server 骨架就绪后实现自动架构测试，接入 `.claude/verify.sh`（越界即失败）。至少覆盖：
    ① 领域/service 层不得 import 框架（gin / gorm）；
    ② 模块只能用其它模块的公共接口，不得 import 其 `internal/`；
    ③ 分层方向单向（handler→service→repo，不得反向）；
    ④ 模块依赖整体无环（Go 编译器已禁包级环，这里补模块级规则）。
    候选工具：golangci-lint depguard、go-arch-lint / arch-go，或基于 go/packages 的自定义检查。
  - 验收：故意写一处越界依赖能被 `verify.sh` 判失败（对应全局 4.8 的 D2 闸门）。

## 阶段 2 · 地基能力（各自 spec-first：先失败测试 → 实现 → 验证 → 独立审查）

> 顺序：多租户 → 认证 → 授权 → 审计 → 合规策略 → 孵化机制（依赖少→多，见 design 依赖图）。

- [ ] **T4 · 多租户基础 / db-per-tenant（D1）** ⛔阻塞(待 T0-a,T1)
  - 输出：控制平面**租户注册表** + 每租户**连接配置 DSN（加密存储 + 密钥管理）**；**自建租户数据源管理器**
    （按租户惰性建/缓存连接池，接入 gale 生命周期，优雅启停）；请求中间件**定位租户→取其库句柄注入 ctx**；
    租户 CRUD。DSN 抽象做到拓扑无关（远程客户库 / 独立实例 / 同实例不同库）；
    实现**租户状态机（初始化中/初始化失败/待激活/正常/锁定/待销毁/销毁中/销毁失败/销毁）+ 租户状态门中间件（fail-closed）**（锁定态默认拒绝、仅放行白名单常量表，销毁不可逆、code 永久占用不复用）；
    **数据源故障治理**（per-tenant 池上限 + 全局 LRU、建连/查询超时、熔断、singleflight、不可达仅该租户失败+告警）；**取连接 ctx 唯一入口 + 句柄租户断言**；**tenantCode 保留字/格式后端强校验**。（整改见 [review-blocks-1-2.md](review-blocks-1-2.md) F1/F3/F4/F5/F7/F10）
  - 验收：**A 租户的请求连不到也读不到 B 租户库/数据**的隔离测试通过（proposal 验收项）；
    某租户库不可达只影响该租户、不拖垮平台。
- [ ] **T5 · 身份认证 authn（D4 口令/会话基线）** ⛔阻塞(待 T0,T4)
  - 输出：登录、JWT 签发/刷新、口令加盐哈希（bcrypt/argon2）、登录失败锁定、会话超时。
  - 验收：登录成功签发可校验 JWT；错误口令/超次锁定/会话超时按策略生效（测试覆盖）。
- [ ] **T6 · 授权 authz / 自研 RBAC（D2）** ⛔阻塞(待 T0-b,T5)
  - 输出：**自研权限表**（用户—角色—权限，权限=资源+动作，可选角色继承），**存各租户库**；
    gin 中间件按 `路由→(资源,动作)` 接口层强制 + Redis 短缓存；
    **预留扩展位**：权限/角色表加可空 `data_scope` 字段、中间件留"数据范围过滤"挂载点（一期 no-op）。
  - 验收：**越权请求被拒**（proposal 验收项）；普通角色限本租户、平台级角色按运营场景的用例通过。
- [ ] **T6b · 数据级权限扩展种子（D2 评估的关键预留）** ⛔阻塞(待 T1)
  - 输出：业务数据访问的**仓储层统一范围注入口**（gorm scope / 统一查询构造）；业务实体**携带归属属性**（owner/部门）。
  - 验收：新增一张业务表即自动经过范围注入口；归属属性随实体落库。（这两项跨 per-tenant 多库回填代价最大，必须提前留。）
- [ ] **T6c · 平台运营中心（D2 新增能力，控制平面）** ⛔阻塞(待 T0-b,T4,T6)
  - 输出：面向平台运营人员的管理能力：创建租户（**幂等 SQL 模板远程初始化业务库** + 版本基线）、重置**租户管理员**密码
    （= 经该租户数据源对其库写，含不可达处理）、租户**生命周期流转**（按 design 状态机）；走**平台级 RBAC**，数据在控制平面中心库。
    高危操作（重置密码等）双人复核 + 通知租户 + 留审计（弥补一期无 MFA，见 review F9）。
  - **🏷️ 额度/坐席/套餐/权益（C3/C5）= 块2「商业化子域」**（本轮不展开详细设计），SSOT=平台中心库。
  - 验收：运营人员可完成上述操作且仅运营/超管角色可见；额度/坐席变更对租户生效（如超额度禁止新建用户）。
- [ ] **T7 · 审计 audit / 独立模块（D3）** ⛔阻塞(待 T0-c,T5,T6)
  - 输出：**独立审计模块**，对内部业务暴露 **API/钩子**：业务**事务内** `audit.Record(ctx,event)` 与业务变更同事务原子落库；
    **gin 中间件**自动采集 HTTP 操作；**统一事件模板**（见 design D3 字段）；**分层落点**（租户事件入租户库、平台事件入中心库）；
    对外/前端**只读**、内部唯一写入；按 时间/操作人/动作/类型 查询 + CSV 导出；当前**全量留存不设期限**。
  - 验收：登录/权限变更/租户运营等产生**可查审计日志**（proposal 验收项）；业务回滚时其审计同事务回滚；
    不存在任何对外写/改审计的接口。
- [ ] **T7b · 审计传播流（可选/二期）** ⛔阻塞(待 T7)
  - 输出：**事务性发件箱(outbox)** + JetStream **统一审计流**，供平台级聚合/监控/(后续)对象存储归档。
  - 验收：业务事务内写 outbox，中继按 event_type 发布到流且不丢（消费者幂等去重）。
- [ ] **T8 · 合规安全策略（D4）** ⛔阻塞(待 T0-d,T5)
  - 输出：**安全策略模块**——口令/会话/锁定等基线抽成**可配置策略**，**全局默认基线 + 按租户可收紧不可放松**；
    底座必备项：传输 TLS、口令加盐哈希（bcrypt/argon2）、敏感数据加密 + 密钥管理。
  - 验收：改策略后 T5/T7 行为随之变化（参数化生效的测试）；租户只能调严不能调松（低于基线被拒）；
    基线项可对照**等保 2.0 三级**清单核验。
- [ ] **T9 · 业务孵化扩展机制 + 示例业务** ⛔阻塞(待 T4,T6,T7)
  - 输出：定义业务模块如何注册路由、复用 租户/鉴权/审计 中间件的**稳定扩展契约**；做一个示例业务系统。
  - 验收：示例业务**复用底座能力跑通最小闭环**（proposal 验收项：证明孵化机制有效）。
