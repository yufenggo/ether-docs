# 块1/块2 · 多维度评审与处置记录

> critic（设计/逻辑）、architect（架构）、security-reviewer（安全）三方独立评审「块1 多租户内核与数据源 + 块2 平台运营中心（含租户状态机）」的结论与**逐条处置**。
> 处置类别：✅已修入设计 ／ 🟦决策已定 ／ ⏭️延后 ／ ⚠️已接受风险 ／ 📌留待 specs/对应块强制。

## 关键澄清（先对齐认知）

- **"客户自托管" vs "我们托管" 架构上无区别**：都是"一租户一独立数据源（一个 DSN）"，代码拓扑无关（D1）。
  因此**数据源故障治理（连接池上限/超时/熔断/不可达降级）是 db-per-tenant 的通用一期基线**，统一适用所有租户，
  **不按托管形态切分、不延后**。（撤销 architect 建议的"客户自托管二期"切分。）

## 处置表

| # | 评审发现（来源） | 严重度 | 处置 |
|---|---|---|---|
| F1 | tenantCode 生命周期矛盾：「删除清理可复用」vs「销毁永久封存」(critic C1) | Critical | ✅ 统一为 **code 一经创建即永久占用**；所有终止路径经「待销毁→销毁中→销毁」封存，**永不复用**；删除半成品库≠释放 code。已改状态机。 |
| F2 | 跨平面写机制空白且 design/breakdown 自相矛盾（重置密码/额度）(三方) | Critical | 🟦 **额度/坐席 = 块2「商业化子域」**（本轮不展开详细设计，SSOT=平台中心库）；**重置密码=平台经该租户数据源对其库写**（就是普通租户库写，无"神秘跨平面"），仅需 F4 的不可达处理。文档不一致已消解。 |
| F3 | 锁定态门禁不可判定、非 fail-closed、读未收口、JWT 未即时失效 (critic C3 / sec C2) | Critical | ✅ 状态门改 **默认拒绝（fail-closed）**；放行=显式白名单常量表（一期仅登录/验证码/登出）；定义各态 **读/写/登录真值表**；锁定即时失效 JWT。已写入设计。 |
| F4 | 数据源管理器故障域空白（池上限/超时/熔断/降级）(arch 最严重) | Critical | ✅ **提为块1 一期基线**：per-tenant 池上限 + 全局活跃池 LRU、建连/查询 ctx 超时、per-tenant 熔断、建池 singleflight 防惊群、ctx cancel 透传、不可达仅该租户失败+告警。 |

| F7 | 状态机缺中间态/guard/并发/幂等 (critic M1/M2/M4, arch) | High | ✅ 加 **销毁中/销毁失败** 态、**待激活/初始化失败→待销毁** 回收路径；每条流转写 guard；中心库**行锁/乐观版本 CAS** 串行化；创建/激活幂等、**初始化 SQL 必须可重入**。 |
| F8 | 远程初始化原子性/幂等/版本基线 (arch / sec H4) | High | ✅/📌 SQL 模板**幂等（IF NOT EXISTS/upsert）** + 写 per-tenant **schema 版本基线** + 网络中断后用版本表对账；初始化高权限账号**最小权限/用后即弃**；模板**参数化防注入** + 版本化防篡改。 |
| F9 | 超管爆炸半径 + 一期无 MFA (sec C4/H5) | High | ⚠️**已接受风险（一期不做 MFA）**：超管/运营一期仅账密+验证码。补偿：高危操作**双人复核 + 强制下次改密 + 失效目标会话 + 通知租户**、平台权限**最小拆分（运营/超管/只读审计）**、登录风控/告警。记入合规风险登记册。 |
| F10 | tenantCode 保留字抢注 / 可枚举 (sec H1/H2, critic M5) | High | ✅ 创建**后端强校验**：唯一性 + **保留字黑名单**（platform/admin/api/login/static/.well-known…）+ 格式正则；未知/异常态租户**无差别响应 + 同等延迟**防枚举；解析端点限流。 |
